# poltergeist

Ask what happened in a [Crucibo](https://github.com/sweet-little-adder/crucibo) backtest without giving an LLM a broker, a shell, or a chance to invent a performance figure.

```console
$ poltergeist "Compare the runs"
Past simulated runs (not a forecast or trading advice):
- bt_DEMO_mean_reversion_001 (DEMO, mean_reversion): return_pct=0.25, pnl_cash=2500, max_drawdown_pct=1.8, fills_count=4 [source: runs/bt_DEMO_mean_reversion_001/run_manifest.json]
- bt_DEMO_mean_reversion_002 (DEMO, mean_reversion): return_pct=-0.12, pnl_cash=-1200, max_drawdown_pct=3.4, fills_count=7 [source: runs/bt_DEMO_mean_reversion_002/run_manifest.json]
Only recorded metrics are shown; no claim about future performance.

trace: traces/runs.jsonl (... ms; prompt=0, completion=0, estimated USD=None)
$ poltergeist "Buy 100 shares now"
I can explain past backtest results, but I can't place trades, access a broker, or advise an order.
```

**The checked-in `DEMO` bundles are synthetic schema fixtures**, not Crucibo production runs, live prices, or a trading result. The example shows the data path and safety boundary, not a profitable strategy. `return_pct` is read verbatim from the manifest's metrics, not independently computed.

## Run it

```bash
git clone https://github.com/sweet-little-adder/poltergeist.git
cd poltergeist
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/poltergeist 'Compare the runs'
.venv/bin/python -m pytest -q
```

Python 3.10+. Runtime uses the standard library. The test extra pins pytest 8.3.5. To query *your* Crucibo runs, pass `--data-root /path/to/crucibo/data` (expects `data/runs/bt_*/run_manifest.json`), generated by Crucibo's `backtest` command. No Crucibo installation or broker credentials are needed. It reads only existing backtest manifests and optional adjacent `metrics.json`; it does not ingest, backtest, or open Parquet files.

## How it works

```
question -> scope guard -> planner -> typed read-only tools -> allowlisted metrics -> cited renderer
                         | offline rules or optional LLM tool-call planner   -> JSONL trace
```

- **Tools:** `list_backtest_runs()` and `get_backtest_run(run_id)` accept no arbitrary paths. Exact run IDs, bounded file size, no symlinks, and an allowlist of numeric metrics keep untrusted manifest text out of the model and answer. No broker, write, shell, or network tool exists.
- **Planning:** default offline mode selects a list or exact run lookup without an API key. An optional OpenAI-compatible chat-completions model can select from the same two function schemas. Its answer text is ignored: the renderer cites only parsed on-disk metrics. Invalid tool arguments fail closed.
- **Answers:** no free-form model synthesis. Numeric claims come from specific run manifests. An absent metric is omitted, and a missing run is reported rather than guessed. Simple execution/prompt-override requests are refused *before* planning; the absence of write tools is the stronger boundary. This is not a general-purpose prompt-injection detector.
- **Observability:** one JSONL row per question records selected tools, counts/errors, mode, wall latency, answer, and provider token usage. Offline runs record zero tokens and unknown cost (`null`), not fake LLM usage.

Optional model planner:

```bash
export OPENAI_API_KEY='your-key'   # don't commit keys
.venv/bin/poltergeist --model YOUR_TOOL_CAPABLE_MODEL 'Summarize bt_DEMO_mean_reversion_001'
# Optional, only if you know this model's current prices per million tokens:
export POLTERGEIST_INPUT_USD_PER_M=YOUR_INPUT_RATE
export POLTERGEIST_OUTPUT_USD_PER_M=YOUR_OUTPUT_RATE
```

The optional planner uses `https://api.openai.com/v1` by default; set `POLTERGEIST_API_BASE` to another **HTTPS OpenAI-compatible** base URL. Provider `prompt_tokens` and `completion_tokens` are recorded if returned. `estimated_cost_usd` is null until both price rates are supplied; it is an estimate, not a bill. API calls cost money under your provider's terms. The offline demo does not make API calls.

## Evaluation

`tests/test_agent.py` checks cited values, exact-run routing, path traversal, unsupported forecasts, prompt-like content in a manifest, and refused execution. `tests/eval_cases.json` defines five reproducible, offline question/answer contract cases. Run `python -m pytest -q`. The eval is deliberately small and deterministic; it does **not** measure live model reliability or financial validity. For a production system, add held-out real runs, model-planner evaluations, authenticated source provenance, schema versioning, and deeper threat modeling.

## Provenance and limits

The reader follows Crucibo's persisted backtest bundle structure in [`reporting/runs.py`](https://github.com/sweet-little-adder/crucibo/blob/77eeb9b2c67b0b41b0d3c9d23f9cb8a087c67d9a/src/crucibo/reporting/runs.py) and [`reporting/bundle.py`](https://github.com/sweet-little-adder/crucibo/blob/77eeb9b2c67b0b41b0d3c9d23f9cb8a087c67d9a/src/crucibo/reporting/bundle.py). Source paths in answers are relative to `--data-root`, not verified cryptographic attestations. The app is research-only, read-only, and intentionally has **no trade execution, broker integration, recommendations, or forecast engine**.

## Web demo and more read-only tools

`public/index.html` is a small no-login interface for the checked-in synthetic runs. Its `/api/ask` endpoint calls the same deterministic planner and renderer as the CLI and exposes a structured trace; it never accepts an API key or broker credential. The endpoint has a 4 KB body limit and 1,000-character question limit. It does not write trace files or persist questions. The demo uses zero model tokens and makes zero model API calls.

The planner also supports two extra scoped tools: `compare_runs(left, right)` computes the difference between recorded return percentages, citing both manifests; `read_note(note)` reads only the allowlisted synthetic `examples/docs/README.md` note and cites that file. These are read-only additions, not a general filesystem or web browser agent. To serve the API locally, point a local HTTP adapter at `api/index.py`; on Vercel, the included `vercel.json` routes `/` to the static UI and `/api/ask` to the Python function. Run `PYTHONPATH=src python -m pytest -q` for the expanded suite.
